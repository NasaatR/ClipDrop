ClipDrop 1.0 Preview — anchored Downloads, adaptive opening and clearer releases.

- User-requested version migration: display 1.0 Preview, native 1.0.0, tag v1.0, assets/root ClipDrop_v1.0. Future personal releases run 1.1,…,1.9,2.0; these are release identifiers, not a public API compatibility signal. Previous0.x tags/assets remain untouched. Preview does not claim production stability.
- Downloads saves the capsule center separately from legacy window offsets. Panel width, rows, density and gaps change around that anchor. Mirroring, display selection/reset and restart retain their intended anchors; old layouts migrate in place.
- Move the icon high to open down, or low to open up. Auto fits available space; Above/Below preferences also respect edge limits. A left-side icon fits the list to its right. Native hover reveal keeps window geometry stable.
- The newest file always lies next to the icon. Upward lists order oldest→newest; downward lists newest→oldest. Opening starts at that edge; arrivals follow it when already there and preserve an older reading position otherwise. Mouse/keyboard/scrollbar capture cancels queued scroll restoration. The underlying Chrome/folder catalog remains newest-first.
- Shared preview simulates top/bottom placement. Row icons lift/scale subtly with eased tint on hover/focus and recycling while scrolling. Render-only motion cancels on unload or disabled animation; no new timer or layout resizing.

Quit via the tray, then install over 0.19 or an earlier release. Installer AppId, data directory, schema 7, browser/native-host IDs and original-file/native-clipboard semantics stay unchanged. The gate tests 0.3.1→current and 0.19→current upgrades, with one installation and unchanged saved data. No dependency or Chrome permission added.

Validation: core geometry/order/anchors/migration/version rollover, native settings anchor stability, upper/lower icon dragging, recent-edge/older-reading scroll behavior, scrollbar ownership, mirror/reset and hover/reduced-motion checks, plus existing WPF/OLE/Chrome/startup/install checks. Physical mixed-DPI hardware, actual File Pilot and third-party editor gestures remain manual/environment acceptance. Next remains stage 5a2b conflict preview/recoverable restore and merge.
